# Learn page (Learning Center) — design

**Date:** 2026-08-29
**Repo checkout:** `C:\GANESH\AgenticAI-Trading 7\AgenticAI-Trading 2` — the live app (the outer
`AgenticAI-Trading 7` is a mirror with no `node_modules`).

## Goal

A new user signs in to AGX and has no idea what to do. There is no help, tour, or
onboarding anywhere in the app today. This adds one **separate page**, reached from the
menu, that teaches the app: a short numbered path for the first session, then a reference
section per feature area, then a glossary.

Scope is the six areas named by the trader: **charts, options, indicators, alerts, MomX
Scanner, Scanner (premarket)**. Everything else gets one line in a "where the rest lives"
map.

## Decisions already taken

| Decision | Choice | Why |
|---|---|---|
| Shape | Workflow-first, then reference | A new user needs a path; a returning user needs lookup. One page serves both. |
| Depth | Explain the concept, then the button | Written so somebody Ganesh invites can use it, not only somebody who already knows what OI and RVOL are. |
| Visuals | Real screenshots with CSS callouts, **plus** text and colour chips | Trader's call, 2026-08-29, overriding the original text-only recommendation. Staleness was the objection; it is answered by making re-capture a single command (`npm run learn:shots`) rather than a manual chore, and by keeping the numbered callouts in CSS so they can be repositioned without re-shooting. |
| Discovery | Menu entry, `?` in the header, auto-open once per browser | A new user cannot miss it; an existing user sees it once. |
| Audience | People Ganesh invites to app.agxtrade.com | Stays quiet about broker keys and data plumbing. Notably it must NOT tell a user to "configure your own keys in Settings" — every user's data currently runs on the first admin's keys, so that instruction would be untrue. |

## Non-goals

Explicitly out of scope, and not to be added opportunistically during implementation:

- No interactive spotlight tour over the live UI.
- No videos or screen recordings.
- No hand-drawn or hand-annotated images. Every screenshot is produced by the capture
  script, and callouts are CSS over the image — never baked into the PNG. An image that
  cannot be regenerated by `npm run learn:shots` does not belong in `frontend/public/learn/`.
- No per-board `?` deep links into individual Learn sections (would touch five existing screens).
- No admin-only section.
- No editing Learn content from inside the app; no CMS; no markdown dependency.
- No data fetching, no polling, no backend endpoint. The page is static.

## Architecture

Four new source files, one capture script, the captured images, and five small edits to
`App.jsx`. Nothing is added inline to `App.jsx`'s
render body beyond the mount point — that file is ~30k lines and, per the comment at the
top of `MomxScannerPanel.jsx`, every panel added to it costs the whole app a re-parse.

```
frontend/src/learnContent.js         pure data, no JSX, no imports from App.jsx
frontend/src/learnScreenshots.js     screenshot manifest: files, alt text, CSS callouts
frontend/src/learnFirstVisit.js      pure "should this open by itself?" decision
frontend/src/LearningCenter.jsx      renders learnContent; presentation only
frontend/public/learn/*.png          the captured images, served statically, not bundled
scripts/capture-learn-screenshots.mjs  Playwright capture, re-runnable
frontend/src/index.css               .learn-* block, APPENDED AT END OF FILE
frontend/src/App.jsx                 nav entry + header ? button + render block + first-visit call
frontend/package.json                "learn:shots" script + pinned playwright devDependency
```

### `learnContent.js` — the content, as data

Exports plain frozen objects. No React, no JSX, no icons — so `node --test` can import it
directly and assert against it.

```js
export const LEARN_STEPS = [        // "Your first 15 minutes on AGX"
  { id, number, title, body: [paragraph, ...], goTo: "<exact nav label>", goToLabel,
    screenshot: "<screenshot id>"|null },
  ...
];

export const LEARN_SECTIONS = [     // the six reference sections
  {
    id, title, icon: "<lucide name>", goTo: "<exact nav label>",
    screenshot: "<screenshot id>"|null,
    concept: [paragraph, ...],      // what this IS, in plain language, before any control
    blocks: [
      { heading, rows: [{ term, meaning }, ...] },      // definition list
      { heading, body: [paragraph, ...] },              // prose
      { heading, chips: [{ label, tone }, ...] },       // colour callouts, see below
    ],
  },
  ...
];

export const LEARN_GLOSSARY = [ { term, plain, id }, ... ];
export const LEARN_ELSEWHERE = [ { goTo: "<exact nav label>", oneLiner }, ... ];
```

`goTo` values must be **exact `optionNavItems` labels** (`"Charts & OI"`, `"Quick Options"`,
`"Auto Alert"`, `"Premarket Scanner"`, `"MomX Scanner"`, …). A test enforces this.

**Colour callouts.** Instead of screenshots, the page shows the app's own colours inline so a
reader recognises them on screen. A chip's `tone` maps to a CSS class only — colour values are
NOT duplicated in `learnContent.js`. The `.learn-chip-*` classes reuse the existing app values:

| tone | Represents | Existing app colour |
|---|---|---|
| `call-wall` | Call / resistance OI wall | `#f23645` |
| `put-wall` | Put / support OI wall | `#2ddf86` |
| `bull` | Bullish candle / cyan signal | `#00ffff` |
| `bear` | Bearish candle / magenta signal | `#ff00ff` |
| `ema9` / `ema21` / `ema50` / `sma200` / `vwap` | The default trend lines | `#d946ef` / `#f6bf4a` / `#22d3ee` / `#15803d` / `#ededee` |

### `learnFirstVisit.js` — open once, never again

```js
export const LEARN_SEEN_STORAGE_KEY = "agxLearnSeen";
export const LEARN_CONTENT_VERSION = 1;

export function shouldAutoOpenLearn({ seenVersion, popoutMode, savedView }) -> boolean
export function readLearnSeen(storage) -> number|null    // never throws
export function markLearnSeen(storage, version)          // never throws
```

`shouldAutoOpenLearn` returns `true` only when **all** hold:

1. `popoutMode` is falsy — a pop-out chart window must never become the Learn page.
2. `seenVersion` is not a number `>= LEARN_CONTENT_VERSION`.
3. `savedView` is empty/absent — a returning browser that already has `agenticActiveView`
   set is mid-workflow and must not be yanked to Learn.

localStorage reads and writes are wrapped in try/catch: `localStorage` throws outright in
some privacy modes, and a storage exception must not take the app down (same rule as
`MOMX_LIST_STORAGE_KEY`).

### `LearningCenter.jsx`

```jsx
export default function LearningCenter({ onNavigate })
```

- Presentation only. Maps `LEARN_STEPS` / `LEARN_SECTIONS` / `LEARN_GLOSSARY` /
  `LEARN_ELSEWHERE` to markup.
- Each step and each section renders a *Take me there* button calling `onNavigate(goTo)`.
- Reference sections are `<details>`/`<summary>` — collapsed by default, native, keyboard
  accessible, zero JS state. The first-15-minutes path is always expanded.
- Wrapped in `memo`. It has one prop and static content; it must never re-render on a poll.
- Icons: import only what is used, by name, from `lucide-react`. A missing icon import does
  not fail the build here — esbuild compiles it to a reference that throws at render time
  (green build, blank page). Every icon name used in `learnContent.js` must resolve through
  an explicit map in `LearningCenter.jsx`, with a fallback, so an unknown name degrades to a
  default icon instead of crashing.

## Screenshots

Verified working on 2026-08-29: Playwright 1.62.1 with Chromium already installed drives
`http://127.0.0.1:5173`, auto-signs in on loopback, renders the full workstation with **zero
page errors**, and screenshots it. The approach below is grounded in that probe, not assumed.

### Rules

1. **Element-scoped, not full-page.** The probe's full-page shot was a 6-across layout at
   3200×1900 — unreadable as a teaching image and far too heavy. Each screenshot targets one
   element by selector (one chart panel, the High OI board, the MomX table).
2. **Callouts are CSS, never baked in.** `learnScreenshots.js` gives each image numbered
   markers at percentage coordinates; `LearningCenter.jsx` absolutely-positions them over the
   `<img>` and prints a numbered legend beneath. Repositioning a callout, fixing its wording,
   or translating it never requires re-shooting. It also keeps the text real text —
   selectable, searchable, and readable by a screen reader.
3. **Regenerable or it does not ship.** Every file in `frontend/public/learn/` must be
   reproducible by `npm run learn:shots`. No manual edits, no hand-drawn arrows.
4. **The script must never touch the trader's browser state.** Playwright runs an isolated
   context; the script seeds its own `localStorage` and never writes to the real profile.

### The capture script

`scripts/capture-learn-screenshots.mjs`, run via `npm run learn:shots` from `frontend/`.
`playwright` is added as a **devDependency pinned to 1.62.1** — it is currently only resolvable
out of an npx cache directory, which is not a reproducible build input.

For each shot the script:
1. Opens an isolated context at 1440×900, `deviceScaleFactor: 2`.
2. Puts the app into a **clean teaching state by driving the UI**, not by seeding storage.
   Verified 2026-08-29: seeding `oiFinderChartLayout` / `oiFinderChartCount` does **not**
   work — `oiFinderChartWorkspace` takes precedence when present, and an `initialLayoutId`
   prop overrides both, so a seeded context still rendered 6-across. The script instead
   clicks `summary[aria-label="Choose chart layout"]` then
   `.oi-chart-layout-menu button[aria-label="Single"]`, which is what a user does and does
   not depend on internal storage keys. The chart workspace is localStorage-only (no
   server-side persistence was found), and Playwright's context is isolated, so this cannot
   affect the trader's real browser.
3. Injects CSS hiding `.signed-in-user` and any account-value element, so no personal
   identity or balance is captured.
4. Navigates to the view, waits for a settle condition (element visible **and** a stable
   frame), then captures that element.
5. Writes the PNG, and prints a table of `id → dimensions → file size`.
6. **Fails loudly** if a target selector is missing or an image exceeds a size budget, rather
   than writing a broken or bloated asset.

Budget: **≤ 250 KB per image, captured at `deviceScaleFactor: 1`.** Measured on 2026-08-29,
not guessed — the chart-plus-chain board comes out at:

| Pixel ratio | PNG | JPEG q88 |
|---|---|---|
| 2 | 594 KB | — |
| 1.5 | 411 KB | 371 KB |
| **1** | **208 KB** | 232 KB |

DPR 1 was checked by eye and is fully legible: the OI wall sizes, the signal labels, the chain
rows and the levels strip all read cleanly. That is because the page caps at 980 px wide, so a
1357 px capture is **already being downscaled** — the extra pixel ratio buys sharpness only on
a retina desktop, at double the bytes. JPEG is rejected outright: it is *larger* than PNG here
and it softens the axis text.

If a shot looks soft on a retina screen, raise that single shot to `scale: 1.5` rather than
moving the default. Cost is further contained by `loading="lazy"` and by the reference sections
being collapsed on arrival, so a reader fetches an image only when they open its section.

shots. The remaining four are best-guess from source and **must be verified by the capture
script failing loudly** rather than silently falling back to a wider element.

**Timing constraint, stated plainly.** The spec is being written on Saturday 2026-08-29 with
the market closed: `/api/premarket-scanner` returns `status: WARMING` with zero rows, so a
Scanner screenshot taken today would show an empty board and teach nothing. `premarket-scanner`
must be captured on a trading morning between 06:00 and 09:30 ET, and `momx-board` reads best
during regular hours. Implementation therefore ships in two passes: everything capturable now,
then a re-run of `npm run learn:shots` on a trading morning to fill those two. **The Learn page
must render correctly with a screenshot missing** — a section whose `screenshot` id has no file
yet falls back to the text-and-chips treatment rather than showing a broken image.

### Manifest

```js
export const LEARN_SCREENSHOTS = [
  { id, file, width, height, alt, capturedOn,          // capturedOn = ISO date
    callouts: [ { n, x, y, text } ] },                 // x/y are percentages, 0-100
];
```

Images render with `loading="lazy"`, `decoding="async"`, and explicit `width`/`height` so
opening Learn does not pull every PNG at once and nothing shifts as they arrive. Each image
carries a quiet "captured <month year>" stamp from `capturedOn`, so a reader can see for
themselves when the picture was taken.

### Part 2 — Reference sections (collapsed)

**A. Charts**
- Concept: one chart, many timeframes; the same ticker read at different speeds.
- Timeframes: 3m, 5m, 10m, 15m, 30m, 1h, 2h, 4h, D, W, M.
- Layouts: Single, 2 side by side, 2 stacked, 3 across, 3 grid, 3 stacked, 4 grid, 4 across,
  4 stacked, 6 grid, 6 across, 7 across, 8 across, MAG7 (all seven side by side), 8 grid,
  9 grid, 10 grid. Up to 10 panels.
- Drawing tools: crosshair/pan, select, trend line, horizontal line, Fibonacci retracement,
  rectangle, brush, text note, price-and-time measure.
- Chart link colours: how two surfaces follow the same ticker.
- Pop-out chart windows.
- Extended-hours shading and session time lines: why candles exist before 9:30.
- Saving: "Save <timeframe> for all tickers" vs "Save <timeframe> chart layout" vs "Reset".

**B. Indicators**
- Concept: an indicator is a second opinion drawn on top of price; more is not better.
- What is on when you arrive, and why: EMA 9 (magenta), EMA 21 (yellow), EMA 50 (cyan),
  SMA 200 (dark green), VWAP (white); OI levels; EMA clouds; MTF 4×8 one-sided clouds;
  Ichimoku; the signal labels; MTF MA levels; session lines; previous day/week/month levels;
  TOS candle colours; and the three lower-pane studies (MTF ADX Clouds, MTF Cloud Label,
  MTF Squeeze 4/10).
- The rest of the catalogue, grouped so it is browsable rather than a wall of 30 names:
  - *Trend lines*: EMA 9 / 21 / 50, SMA 200, VWAP
  - *Clouds*: EMA Clouds (9/21 and 21/50), MTF 4×8 One-Sided Clouds, MTF MACD 6/12/8 Trend
    Clouds, MTF EMA 9×20 Signal Clouds, MTF Squeeze Release Clouds, per-timeframe Cloud
    Bands, CloudMAX MTF EMA 1/5/15
  - *Signal labels*: Call & Put Signals 4×8, Call & Put Signals 9×20, and the Daily→Monthly
    variants (4×8, 9×20, MACD)
  - *Lower panes*: MTF ADX Clouds, Squeeze Momentum, MTF Cloud Label, MTF Squeeze 4/10
  - *Levels*: OI Levels / High OI, PivotPoints, PersonsPivots, MTF MA Levels, Previous
    D/W/M OHLC, Session Time Lines, Extended Sessions, AutoFib, Relative Volume Candles,
    TOS candle colours
- How to turn one on, open its settings, change its colour, and save the profile so every
  ticker on that timeframe inherits it.

**C. Options**
- Concept: what open interest is, what a wall is, and why walls act like magnets and speed bumps.
- Chain tab vs High OI tab; why High OI is the default.
- The live ATM banner: call ATM and put ATM strike, volume, open interest.
- Expected move: what the number means and the high/low range it implies.
- Column meanings: OTM Strike, Exp Move, DTE, Delta, OTM Vol, OTM OI, Vol/OI, ATM Strike,
  ATM Vol, ATM OI, Flow Type, Liquidity Winner, Setup Type, Scanner Tag, Strength.
- HIGH OI Strong / Moderate / Weak badges, and that they use the same scale the chart draws.
- The TOS colour key: CALL ITM, PUT ITM, ATM, HIGH OI, EM HIGH, EM LOW.
- Exporting the same levels as a thinkorswim or TradingView study.

**D. Alerts**
- Concept: an alert is the app watching a price line so you do not have to.
- Auto Alert: a ladder of the biggest call strikes above price and put strikes below is built
  each trading morning at 9:15 AM ET; MAG7 is on by default and you can add your own tickers.
- **Touched vs CONFIRMED** — the distinction that matters most: a wick through a level is an
  early warning and does not advance the ladder; a *completed 5-minute candle closing through
  it* confirms, and the alert then names the next target and how far away it is.
- Sound and browser notification permission.
- Manual price alerts: drawn on the chart, snapping to named levels (previous day high,
  High OI wall, an option strike), and shown as chips on the price axis.

**E. Scanner (premarket)**
- Concept: between 6:00 and 9:30 AM ET, which of the nine big names is waking up.
- The nine tickers.
- CALL2H and CALL4H: momentum signals read from the same chart study you can see, so the
  scanner and the chart cannot disagree.
- Squeeze fires on 1h, 2h, 4h and Daily — and why 15m and 30m are deliberately excluded
  (they fire near-continuously and would drown the score).
- MATCHES / STRONG / LIVE TAPES / FEED at the top. **Corrected 2026-08-29:** an earlier draft
  of this bullet said "STRONG needs more than three hits". That is wrong, and so is the app's
  own card note. `score_strength` (`premarket_scanner.py:641-710`) ranks by the *quality* of
  the cross, not the count: cyan+yellow together or two cyan → STRONG; a single cyan or two
  yellow → MODERATE; one yellow alone → WEAK. Fire-only rows are capped at MODERATE however
  many fire, because a squeeze release is volatility expanding, not direction confirmed.
  `STRONG_THRESHOLD = 3` (`premarket_scanner.py:39`) is dead code, referenced nowhere. The
  Learn page describes the engine's real rule.
- The morning briefing.
- 30-day history in table, calendar, or list view.

**F. MomX Scanner**
- Concept: the wide board — a few hundred names scored the same way every minute.
- What a row has to do to appear: price at least $3; 4-hour volume momentum up at least 0.5%
  versus two bars ago; 1-hour price up at least 0.3% versus two bars ago; **and** at least one
  of a momentum cross, a fired squeeze, or a relative-volume hit.
- The board, left to right: Industry, Symbol, % Chg, the 1D sparkline, RVOL (2h, 4h, D),
  High/Low, RVOL (5m, 15m, 30m, 1h), the white separator column, Squeeze (2h, 4h, D, W),
  Skittles (2h, 4h), Quote Trend, Skittles (D, 2D, 3D, 4D, W, Mo).
- What each means in plain language: RVOL = today's volume against normal for this time of
  day; High/Low = where price sits inside the day's range; Squeeze = pressure building and
  then releasing; Skittles = a fast 0–100 momentum reading, coloured by trend; Quote Trend =
  the last few bars up or down at a glance.
- Refreshes every 60 seconds; the last board you saw is shown immediately while it refreshes.
- Watchlist tabs and the ticker box.

## Honesty constraints on the copy

These are requirements on the words, not on the code:

1. **No claim of decimal-exact thinkorswim parity.** Describe what a column shows. Known gaps
   exist (monthly Skittles is one). The page must not make a promise the data cannot keep.
2. **No instruction to configure personal broker keys.** The per-user key vault exists and is
   not read; all data runs on the first admin's keys.
3. **No internal detail**: no data-source names, no re-auth cadence, no cache behaviour, no
   file or endpoint names.
4. Timings that are user-visible (9:15 AM ET ladder build, 6:00–9:30 ET scan window, 60-second
   MomX refresh) ARE stated, because a user who does not know them will think the app is broken.

1. Fresh browser, no saved view, not a pop-out → opens.
2. Already seen at this version → does not open.
3. Seen at a lower version → opens again (lets a future rewrite re-introduce itself).
4. Pop-out mode → never opens, even when unseen.
5. A saved `agenticActiveView` exists → does not open.
6. `readLearnSeen` / `markLearnSeen` swallow a throwing storage object and do not propagate.

## Risks

| Risk | Mitigation |
|---|---|
| Content goes stale as the app changes | The `goTo` test fails loudly on a page rename. Prose drift is not automatically detectable; `LEARN_CONTENT_VERSION` exists so a rewrite can re-show the page. |
| **Screenshots go stale** — the original objection to having them | Three mitigations: re-capture is one command, not a chore; callouts live in CSS so wording and positions are fixable without re-shooting; each image shows when it was taken. This reduces the risk, it does not remove it — a UI change still silently makes an image wrong until someone re-runs the capture. |
| A screenshot leaks personal data | The capture script hides the signed-in-user element by CSS before shooting, and every PNG is reviewed by eye before it is committed. |
| Page weight on a phone | ≤200 KB per image enforced by the script, `loading="lazy"`, explicit dimensions, and images served from `public/` rather than bundled. |
| Capture blocked by market hours | Two of eight shots need a live session. The page renders without them, and the test pins the pending list so it cannot be quietly forgotten. |
| Auto-open annoys or confuses an existing user | Gated on three conditions; a returning browser with a saved view is never redirected. |
| Bundle size | Static text; the only new dependency is `playwright`, which is a **devDependency** used by the capture script and never shipped to a browser. Images live in `public/` and are not bundled. `LearningCenter.jsx` is imported normally rather than lazily: a lazy chunk that fails to load renders a blank page, which is a worse failure than a few tens of KB. |
| CSS collides with existing rules | New block appended at the very end of `index.css`, all classes prefixed `learn-`. |
